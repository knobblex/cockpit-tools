# Codex 高级席位自动调换

状态：实验性实现，默认关闭；真实工作区验证范围为 ChatGPT Business。

同一团队工作区的一个现有高级席位，在持席成员的订阅额度耗尽后，从绑定 API Key 的有效账号池中循环选择另一位已授权成员。客户端继续使用原 Base URL 和 API Key。调换不保证额度重置；目标成员验证失败时暂停处理。

## 使用

账号列表中存在团队 OAuth 账号时，在 **Codex API 服务 → 概览 → 高级席位自动调换** 中配置。个人账号及缺少团队身份依据的账号不能启用；已有配置或未决操作仍保留处理入口，不影响普通个人账号的 API 服务。

1. 选择目标团队工作区的 Owner/Admin OAuth 授权和一个普通 OAuth 账号池 Key。
2. 确认该 Key 的池内至少有两个同工作区、使用本地 OAuth 接入的成员，包含当前高级成员。界面展示池内顺序，无需另外勾选或排序候选。
3. 探测模型默认留空，程序复用原生服务的模型目录，为每位成员自动选择同时满足 Key 与成员权限的可见模型，跳过储备模型；也可手动指定完整模型名，指定模型无权限时不会改用其他模型。先执行「只读核对」，只检查配置、成员和席位，不提交模型请求、调换席位或开放路由。
4. 阅读工作区影响与探测消耗说明，勾选启用和授权后保存。授权范围会跟随该 Key 后续的池成员变更。后台先验证当前成员，再监测订阅额度。

团队身份只是前置筛选，不代表 Enterprise/Edu 等工作区已支持调换；仍须核对远端 Owner/Admin、有效成员及恰好一个高级席位。只有团队套餐标识而缺少明确工作区结构时，先只读刷新账号资料确认，失败不启用。身份判据见[状态模型](../src-tauri/src/modules/codex_seat_rotation.rs)，不会仅凭个人 Pro/prolite 套餐或填写工作区 ID 放行。

初版仅支持已启用的原生 Rust 网关和一个普通 OAuth Key。模型路由 Key 和 provider gateway 会被拒绝；其他工作区、API Key 账号、官方授权接入、重复身份，以及试用、待变更、停用或无法识别的席位会被排除。启用或有未决操作时不能切换到其他网关引擎。

旧版保存的独立候选名单继续限制原范围和顺序；重新保存并确认授权后，才改为跟随有效账号池，未决操作不能被配置迁移覆盖。

席位变更影响该成员在整个工作区的权益。本机只能协调使用同一 Cockpit 数据目录的原生网关请求，无法等待其他设备或官方客户端的请求结束。

## 自动流程

```text
查询真实成员、席位统计和当前高级成员的实时额度
  → 确认订阅窗口耗尽
  → 从当前持席成员的下一位开始，在有效账号池中循环检查一轮
  → 持久化任务，阻止来源成员的新请求，等待在途请求结束
  → 重新检查授权、成员身份、席位和来源额度
  → 持久化提交记录，只提交一次 swap-seats
  → 核对远端成员席位及统计
  → 刷新目标成员的身份、套餐和真实额度
  → 明确绑定目标成员执行无工具的短请求
  → 再次核对席位与授权，发布有效持席成员
```

自动调换要求有效订阅窗口已耗尽，且接口明确报告限制已达到、不允许请求。已用比例达到 100% 但接口仍明确允许且未达到限制时按可用处理；路由额度冷却复用该判据。缺失或过期窗口、普通 HTTP 429、网络错误、模型限制及界面百分比不作为耗尽证据。

周期监测中的成员列表、席位统计及持席成员额度查询遇到连接失败、超时、HTTP 408、429 或 5xx 时定时重试，沿用原路由验证期限；过期后拒绝请求，核对成功再恢复。额度未知则立即撤销验证，继续核对，不调换席位。旧版成员或统计连接失败、未知额度造成的暂停，仅在已有持席记录、无显式暂停标记和未决操作时自动完整验证。认证拒绝、身份或席位冲突、业务探测失败仍需手动核对；手动调换与未决操作验证失败同样暂停。

候选直接来自 Key 当前有效账号池，并按池内顺序从当前持席成员的下一位开始，末尾绕回池头，每次最多检查一轮。启用、恢复、手动切换及后台提交均检查团队资格；后台持续核对同工作区身份、接入方式、池范围与模型权限，提交前再次确认来源和目标仍合格。候选授权或额度查询失败时跳过并记录原因；没有候选时保留原席位，下一轮继续检查。

标准成员调换前额度为零不直接排除。已经耗尽过的成员需等已知窗口重置并实时确认可用后才能再次成为候选。来源成员的额度冷却不被清空。循环检查候选只在当前高级额度已确认耗尽时进行；额度可用时持续监测当前持席成员。

为防止全部额度耗尽后循环调换，同一工作区因耗尽成功轮换后，30 分钟内再次确认当前成员耗尽时立即暂停，不再等待最短间隔后继续切换。暂停会撤销耗尽成员的路由验证并持久保存；重启或等待保护窗口结束不会自行恢复，需手动核对并恢复。窗口内手动恢复或点击「切换下一位」同样不能绕过保护。健康成员的手动调换不计为耗尽轮换；旧操作缺少触发原因时保守计入保护窗口。

路由发布有有效期，后台用真实成员与额度查询续期。指定 Key 只路由到已验证的高级成员，未验证或过期时返回 `premium_seat_not_verified` 并说明席位核对状态；原有模型限制、账号资格、额度保护和冷却继续生效。其他 Key 在调换期间也不能向来源成员派发新请求或使用尚未验证的目标成员；内部定向探测可以验证目标成员。

轮换后，旧会话通过[上下文重建](../src-tauri/src/modules/codex_native_api/mapping.rs)切到当前席位成员，保留客户端聊天。重建须通过完整历史和归属校验，不向新账号透传旧续接引用，也不修改已有响应归属或重放已执行请求。历史不足时返回错误，需补齐历史、新建会话或等待原账号恢复。

## 暂停与恢复

- **切换下一位：** 保存并启用配置、当前高级成员验证通过后可点击，无需等待额度耗尽。按授权账号池顺序从当前成员之后循环检查，跳过不符合条件的候选；仍遵守最短调换间隔、连续耗尽保护、在途请求等待和完整验证。每次点击只尝试一次调换，无候选时保留现有席位；健康来源成员不会被记为额度耗尽。存在未决操作、暂停或未保存修改时不可点击。
- **暂停调换：** 持久化暂停标记，阻止新的席位提交。已提交操作仍查询远端结果，不能撤销已提交请求。已经验证且仍可用的当前成员可继续通过只读监测续期。
- **重新核对并恢复：** 接受当前远端分配，重新验证授权与额度；若存在未决操作，先核对原操作，只允许新的定向探测，不重复提交调换。
- **核对并确认未执行：** 对提交后仍保持原分配的操作，等待后台要求的核对期限后，由用户明确结束该未决操作。后台再次确认原分配及席位数量后，才允许修改配置或恢复。
- **关闭：** 保存关闭配置，无需继续满足团队资格；存在未决操作时必须先核对结束，不能通过覆盖配置丢弃记录。

调换请求超时或进程重启时，先查询实际分配。远端已完成则继续验证；仍为原分配、席位数量变化、身份变化或其他管理员改动时暂停，不盲目重发、连续换给其他成员或自动换回来源成员。团队资格失效后暂停新操作，但保留已提交操作的只读核对，不绕过资格检查发布路由。调换前中断或等待在途请求超时会取消尚未提交的操作，不中断请求。

目标成员额度尚未生效时进行有界轮询。业务探测每次操作至多自动执行一次，失败或探测期间进程退出后必须手动恢复。成功必须包含完整业务响应，HTTP 200 或流头不视为验证完成。

成员额度接口明确返回 `401 + token_expired` 时，按已观察的令牌代次刷新该成员凭据并重试一次。恢复已提交操作时，会先修复仍在授权池内、身份未变且带有这一认证错误的来源与目标成员，再执行资格和模型校验。其他认证拒绝仍会阻止路由；暂停期间不自动反复刷新成员凭据。

## 接口、存储与限制

管理适配器固定访问 `https://chatgpt.com/backend-api`，使用选定管理员的 OAuth 授权及工作区请求头，遵循账号代理配置。只调用成员列表、席位统计及独立的 `swap-seats` 接口；不接购买、单独升降级或容量修改接口。

请求格式依据 2026-10-20 实际成员管理页面加载的公开前端代码核实，见 [HTTP 适配器](../src-tauri/src/modules/codex_seat_rotation_http.rs)。这是未公开承诺稳定性的管理接口；错误会标明成员查询、席位数量查询或调换提交阶段。只读查询遇到 HTTP 401 时，按已观察的令牌代次刷新管理员凭据并重试一次；HTTP 403 不刷新。暂停后的后台核对不会持续刷新凭据，需显式恢复才能再次尝试。调换 POST 不自动重发，随后只读核对实际结果。认证失败不能直接判定为权限不足，Codex 模型调用授权也不保证成员管理权限。实际费用、调换间隔及权益生效仍由平台决定。实现核对成员席位统计，不声称已读取或验证账单购买容量。

状态保存在 Cockpit 数据目录的独立 JSON 中，配置结构与门禁以[状态模型](../src-tauri/src/modules/codex_seat_rotation.rs)为准；阶段和超时行为以[协调器](../src-tauri/src/modules/codex_seat_rotation_worker.rs)为准。OS 文件锁串行化协调任务，并用共享请求租约等待跨本机进程的在途请求。状态文件损坏、版本不兼容或写入失败时关闭原生路由，直到核对修复。锁文件保留，进程退出由 OS 释放锁。

保留当前操作及最近的已结束操作，包含尝试 ID、成员标识、阶段时间和验证状态。后台仅在阶段、暂停状态或核对消息变化时写入应用日志。席位状态和状态变化日志不记录上游响应正文、令牌或 Cookie。普通 API 服务规则的唯一来源仍是 [API 服务说明](CODEX_API_SERVICE_HANDOFF.md)。

[隔离测试入口](../tests/codex-seat-rotation/Cargo.toml)直接运行生产协调器、HTTP 适配器、原子存储与文件锁，使用本机模拟服务和额度证据，不接触真实工作区：

```sh
cargo test --manifest-path tests/codex-seat-rotation/Cargo.toml --locked
npm test
npm run typecheck
cargo check -p cockpit-tools --lib --locked
```

覆盖团队身份及前后端一致性、入口与旧配置处理、资格失效、池内循环及绕回、旧名单授权兼容、成功发布、权限失败、无候选、POST 响应丢失、重启核对、未执行操作不重发、目标仍无额度、探测失败不重复、暂停与在途请求租约、状态损坏、路由验证过期、认证刷新及连续耗尽保护。真实工作区验证不属于上述隔离测试；执行新的真实调换前需明确来源和目标成员。
